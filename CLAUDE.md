# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Car dealership vehicle management system: browse the inventory for sale, classified by category, with name (make), model, year and price as the core fields. Vite + React 19 + TypeScript front end, Express 5 API in `server/`, SQL Server database.

## Commands

- `npm run db:setup`: create the `VehicleInventory` database if missing, apply `server/db/schema.sql`, seed `server/db/seed.sql` (idempotent)
- `npm run dev:api`: Express API on http://localhost:3001. Node runs the `.ts` files directly (type stripping), and `server/dev.ts` restarts the API when `server/` or `src/` changes. Don't switch back to `node --watch`: on Windows it restarts whenever a dependency lazily loads a file, which drops requests.
- `npm run user -- <name> --role admin|staff`: create an account or reset its password (prompts for it). Also `-- <name> --deactivate` and `-- --list`.
- `npm run dev`: Vite dev server with HMR at http://localhost:5173; proxies `/api` to the API, so run both
- `npm start`: API plus the built `dist/` front end from a single server
- `npm run build`: `tsc -b` type-check (app, vite config and `server/`), then a production build to `dist/`. Use this to verify changes.
- `npm run lint`: Oxlint (config in `.oxlintrc.json`)
- `npm run preview`: serve the built `dist/`

There is no test runner configured.

## Architecture

- **Data model** (`src/types.ts`): `Vehicle` interface plus `CATEGORIES`, an `as const` tuple from which the `Category` union is derived. To add a category, add it to the tuple **and** add a silhouette for it in `SHAPES` in `src/components/VehicleIllustration.tsx`; the `Record<Category, …>` type makes the build fail until you do. Condition badges are styled by class name (`.cond-<lowercase condition>` in `App.css`).
- **Database** (`server/db/`): `dbo.Vehicles` (columns `Make`/`ModelYear` map to `name`/`year`) and `dbo.VehiclePhotos` (ordered photo URLs). Category and Condition are `CHECK` constraints, so adding a category also means updating `CK_Vehicles_Category` in `schema.sql` (and writing a migration for existing databases). Schema scripts must stay re-runnable; batches are split on `GO`.
- **Connection** (`server/db.ts`): configured by `.env` (template in `.env.example`, loaded via `node --env-file-if-exists`). `DB_DRIVER=msnodesqlv8` uses ODBC + Windows auth, which works with the local SQL Express instance without TCP/IP enabled; the default `tedious` driver needs TCP and a SQL login (`DB_USER`/`DB_PASSWORD`). Always pass values as `request.input(...)` parameters, never by string concatenation.
- **API** (`server/index.ts`, queries in `server/vehicles.ts`): `GET /api/vehicles?category=&exclude=&limit=`, `GET /api/vehicles/:id` (404 when missing), `POST /api/vehicles` (201), `PUT /api/vehicles/:id`, `DELETE /api/vehicles/:id` (204), `GET /api/health`. Writes run in a transaction and replace the photo list. Errors are JSON `{ error, fields? }`: 400 for validation, 409 for a duplicate stock number, both with per-field messages in `fields`.
- **Authentication** (`server/auth.ts`): browsing is open to everyone; `POST`/`PUT`/`DELETE /api/vehicles` go through the `requireAdmin` middleware (401 signed out, 403 for `staff`). Accounts are in `dbo.Users` (role `admin` or `staff`) and are managed only with `npm run user` (`server/db/user.ts`); there's no sign-up page. Passwords are hashed with scrypt. Sessions are random tokens in an `HttpOnly; SameSite=Strict; Path=/api` cookie (`Secure` when `NODE_ENV=production`), with only their SHA-256 hash in `dbo.Sessions` (8-hour expiry). Routes: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`. After 5 failed sign-ins for the same username + IP, sign-in is blocked for 15 minutes (in memory). Any new write endpoint must use `requireAdmin`.
- **Passwords** (`pages/PasswordPage.tsx` at `/account/password`, admins only, linked as "Passwords" in the account bar): `POST /api/auth/password` changes your own password after checking the current one, and signs out your other sessions. `GET /api/users` lists accounts, and `POST /api/users/:id/password` resets someone else's password and signs them out everywhere. Resetting your own is refused, so it always needs the current password. Wrong current passwords count toward the same lockout as sign-in. Rules (min 10 chars, max 200, no leading/trailing space) are in `passwordProblem` in `server/auth.ts`, mirrored on the page.
- **Forgot password (no email)** (`server/passwordResets.ts`; pages `ForgotPasswordPage`, `ResetPasswordPage`): "Forgot password?" on `/login` → `POST /api/auth/forgot` records a row in `dbo.PasswordResetRequests`. It answers 202 whether or not the user exists, and allows 5 per IP per 15 minutes. Admins see open requests on the Passwords page (and a badge on "Passwords" in the account bar) and create a one-time link with `POST /api/users/:id/reset-link`. The token is 32 random bytes, only its SHA-256 is stored in `dbo.PasswordResetTokens`, it's valid 24 hours, and a new link replaces the old one. The link is `/reset-password#<token>`: the token sits in the fragment so it never reaches server logs or Referer headers. The page checks it with `POST /api/auth/reset/check` and sets the password with `POST /api/auth/reset`. Any password set (link, admin "Set password", or `npm run user`) goes through `resetPassword`, which ends the user's sessions and clears their requests and links.
- **Comments** (`dbo.VehicleComments`, `server/comments.ts`, `components/VehicleComments.tsx` on the detail page): `GET /api/vehicles/:id/comments` is public (newest first), and `POST`/`DELETE /api/vehicles/:id/comments[/:commentId]` need an admin. The author is the signed-in user. Bodies are plain text (max `COMMENT_MAX_LENGTH` = 2000), rendered with `white-space: pre-wrap`. Never render them as HTML. Comments are deleted with their vehicle; there's no edit.
- **Client auth** (`src/auth.ts`, `components/AuthProvider.tsx`): `useAuth()` gives `{ status, user, isAdmin, login, logout, refresh }`. Hide admin-only controls with `isAdmin`, and wrap admin-only routes in `components/RequireAdmin.tsx`, which redirects to `/login` with `state.returnTo`. Hiding controls is only for the UI; the API check is what enforces it. Navigation state (`from`, `notice`, `returnTo`) and `safePath` (blocks off-site redirects) are in `src/navigation.ts`.
- **Validation** (`src/validation.ts`): `validateVehicle` is shared by the form and the API, so the rules live in one place. It also normalizes values (trims text, upper-cases the stock number, lower-cases the hex color). It's imported by Node, so it imports with `.ts` extensions.
- **Add/edit/delete screens**: `/vehicles/new` and `/vehicles/:id/edit` both render `pages/VehicleFormPage.tsx`. Delete is an inline confirmation on the detail page (`VehicleActions`). After saving or deleting, pages navigate with `state.notice`, which `components/Notice.tsx` (rendered in `App`) shows once. The `NavState` type there describes `{ from, notice }`. Rows are mapped to the shared `Vehicle` type from `src/types.ts`, so the server and the UI use one type definition. Server code must use only erasable TS syntax and import with `.ts` extensions (`tsconfig.server.json`).
- **Client data loading** (`src/api.ts`): `fetchVehicles`/`fetchVehicle` plus the `useRemote(key, load)` hook (loading/error/ready, with retry); `components/RemoteStatus.tsx` renders the loading/error states. The inventory page loads everything once and filters client-side; filter bounds (min year, max price) are derived from the loaded data. The detail page fetches the vehicle and its "similar" vehicles separately.
- **Routing** (React Router, `BrowserRouter` in `src/main.tsx`, routes in `src/App.tsx`): `/` → `pages/InventoryPage.tsx`, `/vehicles/:id` → `pages/VehicleDetailPage.tsx`. Any unknown path also renders the detail page, which shows its "not found" state.
- **Inventory filters live in the URL query string** (`cat`, `q`, `minYear`, `maxPrice`, `sort`, `view`), read and written via `useSearchParams`, with default values left out of the URL. Links to a detail page pass `state.from` (the current path + query), and the detail page's back link uses it so filters are preserved. Keep that pattern when adding new links into the detail page.
- **Photos**: `Vehicle.photos` is an optional list of URLs (files go in `public/vehicles/<id>/`). `src/slides.ts` turns a vehicle into gallery "slides", and `components/VehiclePhoto.tsx` renders one. When a vehicle has no photos, it uses generated SVG placeholders from `VehicleIllustration.tsx` (a category silhouette tinted with `colorHex`). Cards, gallery and thumbnails all render through `VehiclePhoto`, so real photos replace the placeholders everywhere at once.
- **Formatting** (`src/format.ts`): shared `Intl` formatters for USD price and mileage; use them rather than formatting inline.
- **Styling**: plain CSS, no framework. Theme tokens (`--bg`, `--surface`, `--accent`, …) are in `src/index.css`, with a `prefers-color-scheme: dark` override. Component styles are in `src/App.css`. Use the tokens so both themes keep working.
